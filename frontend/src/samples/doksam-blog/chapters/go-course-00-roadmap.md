# Go 강의 로드맵 — 무엇을 어떤 순서로 배우나

이 연재는 다른 언어(Python·JavaScript·Java)로 일해 본 개발자가 Go 로 실제 서비스를 만들고, Go 개발자 채용 면접의 기술 질문에 근거를 들어 답하게 만드는 것이 목표다. 4단계 24편이다. 예시 코드는 글쓴이의 실제 저장소(웹 서버, 데이터 수집 도구, 예약 실행기, 글 검사기)에서 패턴을 가져와 줄이고 일반화했다. 글에 실은 코드와 출력은 모두 직접 돌린 결과다.

## 다 읽고 연습을 풀면 할 수 있게 되는 것

- 표준 라이브러리만으로 HTTP API 서버를 만들고, 테스트를 붙이고, 정적 바이너리와 컨테이너로 배포한다.
- 슬라이스·맵·인터페이스·고루틴·채널이 안에서 어떻게 움직이는지 실험(`-gcflags=-m`, `GODEBUG`, 벤치마크, `-race`)으로 보여 주며 설명한다.
- pprof·trace·벤치마크로 느린 곳을 재고, 잰 숫자로 고친 효과를 말한다.
- 코드 리뷰에서 자주 걸리는 Go 관용구를 스스로 고치고, 시스템 설계 과제를 Go 의 동시성 도구로 풀어 설명한다.

## 이 연재로 되지 않는 것

- 입사를 보장하지 않는다. 채용은 경력, 회사 사정, 면접관에 따라 갈린다.
- 알고리즘 코딩 테스트(자료구조·알고리즘 문제 풀이)는 다루지 않는다. 따로 준비해야 한다.
- 대규모 트래픽을 직접 운영한 경험은 글로 대신할 수 없다. 이 연재는 그 경험을 설명할 말과 실험 방법을 준다.
- Kubernetes, 클라우드 서비스별 사용법, gRPC 생태계는 범위 밖이다. 필요한 곳에서 표준 라이브러리와의 경계만 짚는다.

## 편마다 들어가는 것

질문과 답, 삽화 한 장, 본문, 시니어용 "한 단계 더" 절, "면접에서 이렇게 묻는다" 3~5문항과 모범 답안 요지, 연습 2~3개와 풀이. 기준 툴체인은 Go 1.26.2 이고, 버전마다 다른 기능은 도입 버전을 적는다. 도입 버전은 `$(go env GOROOT)/api/go1.N.txt` 와 공식 문서로 확인한다.

## 1단계 — 입문 (1~6편)

Go 로 작은 서비스를 처음부터 끝까지 만든다. 문법을 나열하지 않고, 실행 파일 → 타입 → 에러 → 서버 → 테스트 → 배포 순서로 하나의 흐름을 따라간다.

| 편 | 제목(가제) | 한 줄 목표 | 선수 편 | 다루는 면접 주제 |
|---|---|---|---|---|
| 1 | 설치부터 첫 실행 파일까지 | 모듈 하나를 만들어 빌드·테스트·교차 빌드까지 돌린다 | 없음 | 모듈과 패키지, `internal`, 대문자 공개 규칙, `go vet`, 교차 컴파일과 `CGO_ENABLED` |
| 2 | 값과 포인터, 구조체와 메서드 | 값 복사와 포인터 공유를 구별해 타입을 설계한다 | 1 | 값 의미론, 제로 값, 값·포인터 리시버, 메서드 집합, 임베딩, 슬라이스·맵 기본 |
| 3 | 인터페이스와 에러를 값으로 다루기 | 작은 인터페이스와 감싼 에러로 경계를 나눈다 | 2 | 암묵 구현, 인터페이스를 쓰는 쪽에서 정의, `%w`, `errors.Is`·`As`·`AsType`, typed nil, panic 과 error |
| 4 | 표준 라이브러리로 HTTP 서버 만들기 | 라우팅·JSON·설정·정적 파일을 의존성 없이 처리한다 | 3 | Go 1.22 ServeMux 패턴과 우선순위, 405, 요청 본문 상한, 환경변수 설정, `go:embed` 제약 |
| 5 | 테스트와 동시성 첫걸음 | 표 주도 테스트와 `httptest` 로 서버를 고정하고 고루틴을 안전하게 띄운다 | 4 | 표 주도 테스트, `httptest`, 고루틴 수명, 채널과 뮤텍스 선택, `context`, `-race` |
| 6 | 배포와 운영 | 정적 바이너리를 셸 없는 컨테이너에 담아 헬스 체크와 종료까지 처리한다 | 5 | 정적 링크, distroless, `/healthz`, 그레이스풀 종료 기초, 의존성 줄이기, gofmt → vet → test 주기 |

## 2단계 — 실무 (7~12편)

혼자 만든 서비스를 팀이 유지보수할 수 있게 만든다. 구조, 버전, 에러, 서버 운영, DB, 테스트 설계를 다룬다.

| 편 | 제목(가제) | 한 줄 목표 | 선수 편 | 다루는 면접 주제 |
|---|---|---|---|---|
| 7 | 패키지 설계와 프로젝트 구조 | 의존 방향이 한쪽으로 흐르는 패키지 구조를 만든다 | 6 | `cmd`·`internal` 배치, 순환 import, 생성자와 옵션 패턴, 문서 주석, 패키지 이름 |
| 8 | 모듈과 버전 | 의존성을 올리고 고정하고 점검하는 절차를 익힌다 | 7 | 최소 버전 선택(MVS), `go.sum`, `replace`·`go.work`, `toolchain` 지시어, `govulncheck`, 주 버전 경로 |
| 9 | 에러 설계 실전 | 계층마다 감싸고 한 곳에서만 기록하는 에러 흐름을 만든다 | 3, 7 | 센티널·타입·동작 확인, `errors.Join`, 로그 위치, `panic`·`recover` 경계, `log/slog` |
| 10 | HTTP 서버 실전 | 미들웨어·타임아웃·그레이스풀 종료·클라이언트 설정을 운영 수준으로 맞춘다 | 4, 6 | 서버 타임아웃 네 가지, 느린 헤더 공격, 요청 `context` 전파, 미들웨어 순서, 클라이언트 타임아웃과 재시도, 레이트 리미터 |
| 11 | 데이터베이스와 database/sql | 연결 풀과 트랜잭션을 이해하고 취소 가능한 쿼리를 쓴다 | 10 | 풀 설정(`SetMaxOpenConns` 등), 트랜잭션과 `defer Rollback`, `context` 취소, NULL 처리, `Rows.Close` 누수, SQL 주입 |
| 12 | 테스트 설계 | 표 주도·골든·퍼즈 테스트로 회귀를 막는다 | 5, 9 | 서브테스트와 `t.Parallel`, 골든 파일, `go test -fuzz`, `testing/synctest`, 테스트 더블, 커버리지의 한계 |

## 3단계 — 심화 (13~21편)

런타임 안에서 일어나는 일을 실험으로 본다. 면접의 "왜 그런가" 질문에 답하는 단계다. 실험으로 못 보이는 부분은 Go 공식 문서와 표준 라이브러리·런타임 소스 주석을 근거로 하고 그렇게 밝힌다.

| 편 | 제목(가제) | 한 줄 목표 | 선수 편 | 다루는 면접 주제 |
|---|---|---|---|---|
| 13 | 슬라이스·맵·문자열의 내부 구조 | 헤더·용량·재할당을 이해하고 공유 버그를 피한다 | 2 | 슬라이스 헤더, `append` 증가 규칙, 배열 공유, 맵 구현과 순회 순서, 동시 맵 쓰기 치명 오류, 문자열·`[]byte` 변환 비용 |
| 14 | 인터페이스 값의 내부 표현 | 타입과 데이터 두 칸으로 인터페이스를 설명한다 | 3, 13 | 인터페이스 값 구조, nil 인터페이스와 typed nil, 동적 디스패치 비용, 타입 스위치, 인터페이스 변환과 할당 |
| 15 | 이스케이프 분석과 스택·힙 | `-gcflags=-m` 으로 할당 위치를 읽고 줄인다 | 14 | 포인터 반환, 인터페이스 박싱, 클로저 캡처, `allocs/op`, 값과 포인터 전달의 실제 비용 |
| 16 | 가비지 컬렉터 | GC 로그를 읽고 `GOGC`·`GOMEMLIMIT` 로 조절한다 | 15 | 동시 마크·스윕, 쓰기 장벽, `GODEBUG=gctrace=1`, `GOGC`, `GOMEMLIMIT`, 할당을 줄이는 법 |
| 17 | 고루틴 스케줄러 G·M·P | 고루틴이 스레드 위에서 도는 방식을 설명하고 누수를 찾는다 | 5 | G·M·P, `GOMAXPROCS`, 선점, 시스템 콜과 블로킹, `runtime.NumGoroutine`, 고루틴 누수 |
| 18 | 채널 내부와 select, context 전파 | 채널의 막힘·닫힘 규칙과 취소 신호의 흐름을 정확히 쓴다 | 17 | 버퍼·무버퍼 채널, 닫힌 채널과 nil 채널, `select` 무작위 선택, `context` 트리와 취소 원인, 시간 초과 |
| 19 | sync·atomic 과 메모리 모델 | happens-before 로 데이터 경쟁을 설명하고 `-race` 로 잡는다 | 18 | 메모리 모델, `Mutex`·`RWMutex`, `Once`·`OnceValue`, `atomic` 타입, `sync.Map`, 경쟁 탐지기의 동작과 한계 |
| 20 | 제네릭 | 타입 매개변수가 필요한 곳과 아닌 곳을 가른다 | 14 | 제약과 `~`, `comparable`, 타입 추론, 구현 방식(GC shape), 인터페이스와 제네릭 선택, 반복자(range-over-func) |
| 21 | pprof·trace·벤치마크로 성능 재기 | 측정 → 원인 → 수정 → 재측정을 숫자로 보인다 | 15, 16, 17 | 벤치마크 작성(`b.Loop`), 결과 비교, CPU·힙 프로파일, 실행 추적, PGO, 마이크로 벤치마크의 함정 |

## 4단계 — 면접·설계 (22~24편)

앞의 내용을 면접 형식으로 꺼내 쓴다.

| 편 | 제목(가제) | 한 줄 목표 | 선수 편 | 다루는 면접 주제 |
|---|---|---|---|---|
| 22 | 코드 리뷰에서 걸리는 관용구 | 리뷰어가 짚는 Go 관용구를 고쳐 쓴다 | 1~21 | 이름 짓기, 에러 문자열, 리시버 일관성, 루프 안 `defer`, `context` 위치, 빈 슬라이스와 nil, 불필요한 고루틴 |
| 23 | 시스템 설계 과제를 Go 로 풀기 | 레이트 리미터·작업 큐·단축 URL 을 요구사항부터 장애 대응까지 설계한다 | 10, 11, 18, 19 | 요구사항 정리, API·저장소 설계, 동시성 모델, 관측(로그·지표), 장애와 재시도, 용량 추정 |
| 24 | 모의 면접과 라이브 코딩 | 질문 은행과 라이브 코딩 과제로 실전처럼 연습한다 | 전부 | 워커 풀, LRU 캐시, 동시 크롤러, 질문 은행, 답안 채점 기준 |

## 진행 상태

2026-11-18 기준으로 1~24편 원고를 다 썼다. 제목은 원고를 쓰면서 결론 문장으로 바꿨다.

13편 이후 원고는 그때 아직 올라가지 않은 편을 "로드맵의 N편" 으로 쓰고 이 로드맵 주소에 링크했다. 그 편이 올라가면 실제 주소로 바꾼다.
