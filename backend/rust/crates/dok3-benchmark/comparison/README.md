# Tantivy 분석기 변경 전후 비교

기준 커밋은 `fb0c336d2a64a5e0426d96314b3a92a031cbc858`이다. 같은 Rust 벤치마크로 이 커밋의 Tantivy 스키마 v1과 Slice A의 v2를 비교했다. 기존 디스크 색인은 원본 문서로 새 generation에서 재색인해야 한다. v2 코드는 스키마가 다른 기존 디렉터리를 열 때 오류를 반환한다.

## 재현

저장소에서 Tantivy 의존성을 캐시에 준비한 뒤 실행한다.

```sh
sh backend/rust/crates/dok3-benchmark/comparison/run.sh fb0c336
```

스크립트는 기준 커밋에서 임시 Cargo 워크스페이스 두 개를 만들고 후보에만 현재 분석기와 색인 코드를 복사한다. 벤치마크가 두 버전의 실제 `TantivyIndex`를 호출할 수 있도록 임시 워크스페이스에 직접 의존성을 추가한다. 두 버전을 release로 빌드하고 동일한 입력과 설정으로 실행한다.

## 결과

macOS 26.6.2 arm64, Rust 1.100.0에서 측정했다. RAM 색인에는 배경 문서 1,000개, 질의별 공개 문서 7개와 내부 문서 7개를 넣었다. 각 질의의 Recall@5와 MRR@5를 구해 평균을 냈다.

| 지표 | v1 | v2 |
| --- | ---: | ---: |
| Recall@5 | 0.7143 | 1.0000 |
| MRR@5 | 0.7143 | 1.0000 |
| 금지 문서가 노출된 질의 | 0 | 0 |
| ACL 집계·관련 검색어 노출 또는 권한 없는 범위의 응답 위반 | 0 | 0 |
| 내부 권한으로 해당 문서를 찾은 질의 | 5/7 | 7/7 |
| 부하 요청 오류 | 0/14,000 | 0/14,000 |

v1은 `write x`와 `load x`로 복합 식별자를 찾지 못했다. v2에서는 일곱 질의 모두 기대 문서가 첫 번째 결과였다.

검색 지연은 질의별 4개 스레드에서 각각 50회 예열 후 500회씩 실행해 측정했다. 스니펫과 집계가 포함된 응답의 지연을 밀리초로 표시했다.

| 질의 | p50 (v1 → v2) | p95 (v1 → v2) | p99 (v1 → v2) |
| --- | ---: | ---: | ---: |
| camel | 0.0533 → 0.0884 | 0.0876 → 0.1245 | 0.1044 → 0.1418 |
| pascal | 0.0399 → 0.0723 | 0.0470 → 0.1078 | 0.0506 → 0.1223 |
| snake | 0.0888 → 0.0732 | 0.1151 → 0.1043 | 0.1299 → 0.1200 |
| namespace | 0.2019 → 0.2372 | 0.3054 → 0.3191 | 0.3474 → 0.3515 |
| code | 0.1857 → 0.1887 | 0.2619 → 0.2325 | 0.3001 → 0.2698 |
| korean | 0.0819 → 0.0848 | 0.0928 → 0.0955 | 0.1019 → 0.1021 |
| acl | 0.1742 → 0.1873 | 0.2638 → 0.2752 | 0.2969 → 0.2969 |

복합 식별자 검색이 가능해진 두 질의에서 지연이 늘었다. 가장 높은 p95는 `cache::lookup`에서 0.3054 ms에서 0.3191 ms로 늘었다. 지연 수치는 단일 로컬 실행과 합성 코퍼스에서 측정했다.

## #57 국문 조사·복합어 정규화

한국어 질의 10개에서 Recall@5와 MRR@5가 각각 0.20에서 1.00으로 올랐다. 기준 커밋은 `d26bc1fe47ac0165edb279bd0add904607e0716e`다. macOS arm64와 Rust 1.100.0에서 측정했다.

```sh
CARGO_TARGET_DIR=/tmp/dok3-target-p2-2 sh backend/rust/crates/dok3-benchmark/comparison/run.sh d26bc1f korean
```

같은 Tantivy 색인 코드로 두 버전의 RAM 색인을 새로 구축한다. 각 색인에는 배경 문서 1,000개와 질의별 공개·내부 문서 각 1개를 넣는다. 질의는 조사 교체, 붙여 쓴 복합어, 띄어 쓴 구성어를 포함한다. 질의별 상위 5건에서 기대 문서의 검색 여부와 첫 순위의 역수를 계산한 뒤 평균을 낸다.

| 지표 | 기준 | 정규화 적용 |
| --- | ---: | ---: |
| Recall@5 | 0.20 | 1.00 |
| MRR@5 | 0.20 | 1.00 |
| 금지 문서가 노출된 질의 | 0 | 0 |
| ACL 집계·관련 검색어·범위 검증 위반 | 0 | 0 |
| 내부 권한으로 해당 문서를 찾은 질의 | 2/10 | 10/10 |

비교 스크립트는 두 버전의 지표와 ACL 위반 건수를 검증한다. 이 수치는 정규화 사례에 맞춘 합성 코퍼스에서 측정했다. 기존 디스크 색인에 새 검색어를 반영하려면 원문으로 새 세대를 구축해야 한다.
